Building from source ​

Requirements ​

ATMO builds with xmake and a C++23 compiler:

PlatformCompilerAlso needed
WindowsMSVC
macOSclang++Xcode, only to build the Vulkan platform (MoltenVK)
Linuxg++Development packages for X11, Wayland and audio (see below)

See the xmake quick start to install xmake.

Linux packages ​

SDL3 is built from source and needs the system development packages for X11, Wayland and audio. Vulkan needs libvulkan1 and a driver. On Debian and Ubuntu:

sh
sudo apt-get install -y --no-install-recommends \
    build-essential git make pkg-config cmake ninja-build \
    libasound2-dev libpulse-dev libaudio-dev libfribidi-dev libjack-dev libsndio-dev \
    libx11-dev libxext-dev libxrandr-dev libxcursor-dev libxfixes-dev libxi-dev \
    libxss-dev libxtst-dev libxkbcommon-dev libdrm-dev libgbm-dev libgl1-mesa-dev \
    libgles2-mesa-dev libegl1-mesa-dev libdbus-1-dev libibus-1.0-dev libudev-dev \
    libpipewire-0.3-dev libwayland-dev libxinerama-dev \
    libvulkan1 mesa-vulkan-drivers vulkan-validationlayers

The engine's CI installs the same list, in the "Install SDL3 build dependencies" step of .github/workflows/build.yml.

Clone and build ​

sh
git clone https://github.com/ATMO-Engine/atmo.git
cd atmo
xmake

xmake builds the atmo target (engine and editor) in debug mode. Then start it with:

sh
xmake run atmo

The first xmake run downloads and builds every third-party library, including the Slang shader compiler, so it takes a while. Later builds reuse them. There are no git submodules to initialize.

Other targets and modes ​

CommandResult
xmake -m releaseOptimized build (-O3)
xmake build atmo-testCatch2 unit test binary
xmake test -vRun the unit tests
xmake build atmo-exportExport-only runtime, without the editor
xmake clean --mode=softRemove build artifacts
xmake clean --mode=fullRemove build artifacts and generated files
xmake clean --mode=allAlso uninstall the project's packages (rebuilt on next run)

Debug builds enable AddressSanitizer and UndefinedBehaviorSanitizer on platforms other than Windows. xmake f -m debug --tsan=y uses ThreadSanitizer instead.

Build options ​

Options are set once with xmake f and kept for later builds.

OptionDefaultEffect
--rendering_metal=y|non for macOSBuilds the Metal rendering platform
--rendering_vulkan=y|non for Windows and LinuxBuilds the Vulkan rendering platform
--tsan=y|noffThreadSanitizer in debug builds, instead of ASan/UBSan
--coverage=y|noffWrites a coverage report after xmake test

Test coverage ​

sh
xmake f --coverage=y
xmake build atmo-test
xmake test -v

With --coverage=y, atmo-test is built with coverage instrumentation, and each xmake test run prints the line, function and branch coverage of src/ and writes build/coverage/:

FileContent
build/coverage/html/index.htmlBrowsable report, with the hit count of each line
build/coverage/lcov.infoLCOV data, for editor extensions such as Coverage Gutters

The report needs clang or g++, so it is not available with MSVC:

  • clang uses LLVM source-based coverage. On macOS, llvm-profdata and llvm-cov come from Xcode. Elsewhere they are looked up on the PATH, or in the LLVM_PROFDATA and LLVM_COV environment variables, and must match the clang version.
  • g++ uses gcov, and the report is made by gcovr (pipx install gcovr).

Each run replaces the previous report. Release builds report less precise line counts than debug builds, because optimized code no longer maps exactly to source lines. xmake f --coverage=n removes the instrumentation again.

Command-line options ​

Pass options to the engine after the target name, for example xmake run atmo --headless. --help lists them all.

OptionEffect
--headlessStarts without a window, using the Null rendering platform
--rendering-platform=metal|vulkan|nullAsks for a rendering platform
--gpu-validationTurns on the rendering platform's validation
--render-thread=on|offoff renders on the main thread, which keeps stack traces readable
--lang=<language>Overrides the detected user interface language

Third-party dependencies ​

Third-party libraries are installed by xmake's package manager from xmake-repo.

  • Versions are declared with add_requires in xmake.lua.
  • The exact versions in use are recorded in xmake-requires.lock. Commit it whenever a version changes.
  • Recipes for versions or options xmake-repo does not provide yet live in deps/packages/.
  • Built packages are cached in ~/.xmake/packages and shared between checkouts.

To change a dependency version, edit its add_requires line, then run xmake f -y and commit the updated lock file.

WARNING

The lock file matches the default configuration of each platform. Do not commit the xmake-requires.lock changes that --rendering_vulkan=y causes on macOS.
