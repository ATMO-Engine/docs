Adding an entity or a component ​

This page is for contributors to the engine. It adds Coin2d, an entity with a Coin component. The build compiles every .cpp file of src/: there is no list of files to update.

Header ​

cpp
#pragma once

#include "core/ecs/entities/2d/entity_2d.hpp"
#include "core/ecs/entity_registry.hpp"
#include "meta/meta.hpp"

namespace atmo::core::components
{
    struct Coin {
        int value = 1;
        float spin_speed = 90.0f;
        bool collected = false;
    };
} // namespace atmo::core::components

template <> struct atmo::meta::ComponentMeta<atmo::core::components::Coin> {
    static constexpr const char *name = "Coin";
    static constexpr const char *category = "2D";
    static constexpr auto fields = std::make_tuple(
        atmo::meta::field<&atmo::core::components::Coin::value>("value"),
        atmo::meta::field<&atmo::core::components::Coin::spin_speed>("spin_speed").withRange(0.0f, 720.0f));
};

namespace atmo::core::ecs::entities
{
    class Coin2d : public EntityRegistry::Registrable<Coin2d, Entity2d>
    {
    public:
        using EntityRegistry::Registrable<Coin2d, Entity2d>::Registrable;

        static void RegisterSystems(flecs::world *world);

        void initialize();

        static constexpr std::string_view LocalName()
        {
            return "Coin2d";
        }

        void collect();
    };
} // namespace atmo::core::ecs::entities

Source ​

cpp
#include "coin_2d.hpp"

#include "core/ecs/world_context.hpp"
#include "meta/auto_register.hpp"

namespace atmo::core::ecs::entities
{
    void Coin2d::RegisterSystems(flecs::world *world)
    {
        const auto *ctx = world->try_get<components::WorldContext>();
        if (ctx && ctx->is_editor_isolated)
            return;

        world->system<components::Coin, components::Transform2d>("Coin2d_Spin")
            .kind(flecs::OnUpdate)
            .each([](flecs::entity e, components::Coin &coin, components::Transform2d &transform) {
                if (!coin.collected)
                    transform.rotation += coin.spin_speed * e.world().delta_time();
            });
    }

    void Coin2d::initialize()
    {
        Entity2d::initialize();

        setComponent<components::Coin>({});
        createSignal<int>("Collected");
    }

    void Coin2d::collect()
    {
        auto &coin = getComponentMutable<components::Coin>();
        if (coin.collected)
            return;
        coin.collected = true;
        getSignal<int>("Collected").emit(coin.value);
    }
} // namespace atmo::core::ecs::entities

ATMO_REGISTER_ENTITY(entities::Coin2d);
ATMO_REGISTER_COMPONENT(atmo::core::components::Coin)

The entity ​

Registrable gives the entity its full name, made of those of its parents and its LocalName: Entity::Entity2d::Coin2d. EntityRegistry creates entities by full name:

cpp
auto coin = EntityRegistry::Create<entities::Coin2d>("Entity::Entity2d::Coin2d");
coin->setParent(parent);
  • Entity::RegisterSystems must be declared, even when it is empty. Otherwise the one of the parent is found instead, and its systems are registered twice.
  • Entity::initialize must call the one of the parent first, which adds the components of the parent.
  • An abstract class, such as Body2d, is registered but cannot be created.
  • An entity object is only a handle. Copying it does not copy the entity, and all its data must be in components.
  • Use EntityRegistry::CreateIn to create an entity in the world of a scene editor. HierarchicRegistry::Create uses the main world.

Register it ​

MacroAlso sets
ATMO_REGISTER_ENTITYNothing
ATMO_REGISTER_ENTITY_ICONThe icon in the editor
ATMO_REGISTER_ENTITY_COLORThe color of the icon
ATMO_REGISTER_ENTITY_ICON_COLORBoth

Without an icon or a color, those of the parent are used. These macros, and the ones that register events and bindings, define a variable named _: use one per .cpp file. ATMO_REGISTER_COMPONENT has no such limit.

Name it ​

Add the name of the type to translation/en-US/atmo.json, under atmo.entities. Without it, new entities are named atmo.entities.Entity::Entity2d::Coin2d#12.

json
"Entity::Entity2d::Coin2d": "Coin2d"

The component ​

ComponentMeta describes the fields that are saved, shown in the inspector and available to the MCP server. Fields that are not listed, such as collected, only exist while the engine runs.

  • name identifies the component in scene files. It must be unique: a second component with the same name is ignored.
  • Keep the names of the fields stable. In a file, an unknown field stops the reading of its component without any message.
  • Fields can be added: files without them keep the default value.

Fields can have these options:

OptionEffect
FieldDescriptor::withWidgetUses that widget in the inspector
FieldDescriptor::withRangeGives the range of a number
FieldDescriptor::withLabel, FieldDescriptor::withTooltip, FieldDescriptor::withCategoryDescribe the field
FieldDescriptor::asReadOnlyCannot be changed through reflection
FieldDescriptor::skipFlecsIs not declared to Flecs. Needed for types it does not know, such as vectors and variants.

ATMO_REGISTER_COMPONENT_NO_FLECS registers a type that is never a component of an entity, such as a subresource or a section of the project settings.

Widgets ​

These field types have a widget in the inspector:

TypeWidget
int, float, bool, std::stringint, float, bool, string
Vector2, Vector2i, Vector3, Vector4vector2, vector2i, vector3, vector4
types::Colorcolor_picker
std::vector of a type with a widgetvector

file_path and subresource_list are set by name or by the field type. Any other type, such as an enum, a uint16_t or a structure, is shown without a way to change it. Vector3i and Vector4i name a widget that does not exist.

A new widget is registered in the WidgetRegistry with ATMO_REGISTER_WIDGET: see src/editor/widgets/. DefaultWidget selects it for a type.

Systems ​

  • The same RegisterSystems runs for the game and for each scene editor. Return early when WorldContext::is_editor_isolated is set, for anything that must not happen while editing.
  • Systems run while the world is read-only. To create or destroy entities, use SignalQueue::Enqueue: see The signal queue.
  • To free resources, add an observer for flecs::OnRemove on the component, as entities::Sprite2d does.
  • Project settings read in RegisterSystems are the default ones in run mode: see late settings. Read them when the system runs instead.

Children ​

An entity can create children in initialize. Children are saved with the scene, and created again when it is loaded: the entity then has them twice. Avoid it for entities meant for scenes.

To reach a child, use its index in Entity::getChildren, whose order is kept, as UiDropdownMenu::getLabel does, or capture a handle in the lambda that needs it. Do not look children up by name, and do not store a flecs::entity in a component.

Check it ​

  1. Build, and add the entity in the scene editor.
  2. Save the scene, close its tab and open it again: the fields must keep their values.
  3. Run the game.
  4. Run xmake test -v.

To use the entity from scripts, see Adding a Luau binding. Without a binding, scripts get the methods of its closest parent that has one.
